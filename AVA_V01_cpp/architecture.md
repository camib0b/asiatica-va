# Codebase Architecture

- main.cpp  is the application entry point containing main(). It initializes a QApplication with metadata and icon, applies a light theme, bootstraps configuration/locale/defaults, creates and shows the MainWindow on the stack, then runs the Qt event loop.

## UI Views

- WelcomeWindow builds a centered Qt UI for the app splash with a title and an import button (with dynamic width calc). It wires signals, applies i18n strings, and plays a short entrance.
- GameSetupWindow is a Qt QWidget that builds a configurable form UI for home/away team names, abbreviations, colors, optional game date, and language selection; it integrates with GameMetadataSuggester for AI-driven auto-population from video paths and derives abbreviations via a simple character-collection routine.
- WorkWindow implements the main application UI with dynamic mode-based layouts (Tagging/Analyzing/Presenting), coordinating VideoPlayer, TagSession, splitters, tag table, notes, and presentation queue. Opening a video saves the previous match when one is already open, then loads the session for the new source paths. Closing the video, or quitting with a video open, saves first. A missing session file starts from Camila's layout. A corrupt or newer file is left on disk and is not applied. WorkWindow keeps a one-line notice on screen, in the current language, that the session file could not be read and changes to this match will not be saved, and logs that fact.
- MainWindow acts as the top-level Qt UI orchestrator, using a QStackedWidget to manage transitions between WelcomeWindow and WorkWindow. It drives video import/concatenation flows (via VideoConcatenator and QTemporaryDir), maintains a TagSession, and handles locale and shutdown cleanup.
- StatsWindow is a Qt QWidget displaying hierarchical event statistics for a TagSession, with team (home/away/both) filtering via QButtonGroup/QToolButtons and a QTreeWidget showing main/follow-up counts plus percentages. Core design centers on signal-driven rebuildTree() that aggregates tags, applies filters, sorts case-insensitively, and populates tree items with UserRole metadata for double-click navigation.
- PresentationPanel is a Qt widget implementing a presentation panel for filtering, selecting, and exporting tagged clips from a TagSession, with a checkable table sorted by time, lead/lag spinbox controls for the current clip, and UI state synchronization. The clip list uses the shared work-list chrome (`Style::configureWorkDataView`).
- PresentationInstancesModel is a QAbstractTableModel for presentation-mode tag instances (time, team, event columns) with checkable rows, current-clip highlighting, and a RAII bulk-update guard that suppresses checkStateChanged during programmatic updates.
- ClipDurationSettingsDialog implements a Qt dialog for configuring per-event lead/lag clip durations in a grid layout, pulling defaults from EventDefaults, updating a TagSession on changes, and supporting full reset. It manually manages a dynamic set of labels and spinboxes with parented QWidget ownership. Row labels come from EventLabelResolver. The QSettings key for each row is the catalog id. A value still stored under the canonical English name is copied onto that id when durations load, and the name key is removed.
- XmlEventMappingDialog presents a table UI for mapping XML event codes to canonical events/teams with auto-detection based on abbrev patterns (+/- suffixes), performs validation, and constructs ordered TagSession::GameTag objects with time offset and period inference.
- XmlSyncDialog is a Qt QDialog that lets users align XML-imported subtitle timings to a VideoPlayer by setting a time offset from an XML anchor point to the current video playhead. It builds a form with labels and buttons, updates a live preview of affected instances (including out-of-bounds clamping counts), and uses standard Qt raw-pointer + parent-child ownership for its widgets.

## Components

- FollowUpCatalog reads the follow-up tree, payload layout, team-switch flag, and goal-continuation flag from EventCatalog, and formats the arrow path.
- GameControls is a complex Qt QWidget for sports event tagging, featuring team selection with color styling, game-phase management for quarters, a main grid of event buttons built from EventCatalog, dynamic multi-level follow-up prompts, extensive keyboard shortcuts, arrow-key focus navigation, and signal emission for tag commits. Period advance (G/H), follow-up number keys, and Escape stay in this widget. Shortcut and hidden overrides are applied here: a hidden button stays in its grid hole and does not tag, and the first visible button in keyboard order keeps a shared key. Follow-up visibility uses a path hidden flag when one is stored. A right-click menu renames, changes the key, hides or shows, and edits existing follow-ups. Renaming or hiding a follow-up that also appears under a different main button asks first, and can apply to every use or only to the selected path. A follow-up that only repeats inside one main button changes every branch of that button. There is no edit-in-place mode on the live grid. The menu and the gear action open GameControlsEditorDialog.
- MatchNotesEditor is a QTextEdit subclass providing rich-text editing for match notes with @mention autocomplete for tags via a QListWidget popup, inserting mentions as HTML anchors that emit activation signals on click while preserving scroll position and supporting HTML serialization.
- TeamColorPicker is a compact Qt widget providing a clickable color well that opens a popup with a fixed localized palette, live hex editor, and system color picker fallback. Key design uses a custom-painted ColorCircleButton (with luminance-based borders), manual popup positioning, and tight state synchronization across the well, swatches, and text field via normalized hex strings.
- TimelineBar is a Qt media timeline widget with a custom ClickSeekSlider supporting direct click-to-seek, a label that toggles to an editable time field on click, throttled scrub events, and stateful synchronization between user seeking and external position updates. Key design uses flags (isScrubbing_, waitingForSeekCommit_) plus a tolerance timer to avoid feedback loops.
- VideoControlsBar is a Qt QWidget implementing a horizontal layout of playback controls (play/pause/seek/speed/mute buttons plus speed label). It wires signals for commands and visual flash effects, manages application-wide keyboard shortcuts behind media/focus gates, updates localized UI strings, and maintains playback/mute state with style variants.
- VideoPlayer is a QWidget subclass that encapsulates QMediaPlayer, QVideoWidget, controls, and timeline for playback with seeking, rate control, keyboard shortcuts, stall detection/recovery, and macOS-specific system sleep/wake state restoration.

## State
- EventCatalog is the single definition of each main event and follow-up: stable id, canonical English name, keyboard key, button-grid row and column, XML code, factory lead/lag, follow-up children, Spanish text, an optional display label, and the goal / shoot-out flags (scoresGoal, continuesAsGoal, isShootout, shootout attempt result). Game tags store those ids. Clip-duration QSettings use the same id. XML `<code>` and the .clips.json `code` field still use the canonical English name or short code.
- EventLabelOverrides is the in-memory rename table for one TagSession, keyed by EventCatalog::EventId. An entry may store a label, a shortcut key, and a hidden flag. That id-level record applies to every place the id appears. A follow-up path (main event plus chain) may also store its own label or hidden flag, and that record wins for that path only. Shortcuts stay on the id. GameControls applies the label, the shortcut, and the hidden flag. A hidden event is not a visible sibling when a new label is checked for duplicates. The table still accepts two events that share a key, so an older file loads; the editor refuses to save a new conflict. TagSession::clear() drops tags and keeps the table. The match session file and named control templates persist the table. Nothing in the table is written to QSettings. Opening a match that has no session file clears the table, so a new match starts on the catalog labels.
- EventLabelResolver is the display text for a catalog id after those overrides. A stored label replaces the catalog text in both English and Spanish. When a tag line knows its main event, each follow-up step uses a path label if one is stored. GameControls button titles, follow-up popups, the tagging toast, the tags table, its filter menu, stats, presentation filters, the presentation stage, clip-duration names, session-note headings, compilation filenames, and the .clips.json overlay label all read it. Stats counts and clip-duration rows stay grouped by catalog id. GameControls reads shortcut and hidden from the same table, and follow-up visibility from the path when a chain is open. Tag ids, follow-up payloads, and the export codes above stay on the catalog. Follow-up renames are not written to XML or .clips.json.
- EventDefaults manages factory and user-overridable lead/lag clip durations. Play-event defaults and the configurable list come from EventCatalog. Start-anchor, timeout, and quarter codes stay here. QSettings overrides live under the `clipDurations` group. Each subgroup is the decimal catalog id, with `preMs` and `postMs`. A subgroup still named with the canonical English name is copied onto the id on load and then removed. The previous writer percent-encoded characters outside the unreserved set, so a space became `%20` and the dot in `S.O.` stayed a dot. A value stored under the raw name is still read when that name differs from the encoded group. An id subgroup wins when both exist.
- EventControlsSetup is the controls payload shared by a match session and a template: the label, shortcut key, and hidden flag for each catalog id, plus optional path-scoped label and hidden overrides. An id-level record is the all-instances case. The catalog does not add, remove, or reorder follow-up nodes, so a setup does not carry a second tree. `builtinDefault()` is an empty table, the catalog as shipped, and its only name is Camila's layout. GameControlsEditorDialog keeps a draft and calls `fromSession` on open and `applyToSession` on Save. Reset and Load change the draft only. Templates go through EventControlsTemplateStore and are reused across matches. The dialog is full screen. Its grid matches the tagging keyboard, and the selected key's follow-ups are an indented tree. Cancel drops the draft.
- EventControlsTemplateStore keeps named setups in `control-templates.json` under the application data directory (`format` `ava-control-templates`, version 2). Version 1 files load with no path overrides. `listTemplates`, `saveTemplate`, `loadTemplate`, and `removeTemplate` are the editor API. Camila's layout is always listed first and is not written into the file, so it cannot be replaced or deleted. A missing file means only that built-in layout. A corrupt file or a newer version is not overwritten.
- MatchSessionFile is the versioned per-match JSON (`format` `ava-match-session`, version 2). It lives in the application data directory under `sessions/`, and the file name is the SHA-256 of the ordered canonical source-video paths joined by newlines. Playback of a multi-file import is a temporary concatenation that is deleted on close, and the video folder may be read-only, so the session is not a sidecar beside the media. `.clips.json` stays the export sidecar and is a different schema. The file stores team metadata, the match note, tags in insertion order (ids, follow-up ids, clip intervals, notes), the controls setup, clip lead/lag overrides, the presentation selection, and telestration drawings (normalized shape, timestamp, hold, optional tag id). Version 2 adds `pathOverrides` beside `labelOverrides`. Version 1 files load with no path overrides. A missing file is a new match. A corrupt file or a newer version is not applied and is not overwritten. WorkWindow tells the user that changes to this match will not be saved. Unknown keys are ignored on load. The setup form is seeded from a loaded file and skips the metadata suggestion; confirming the form keeps the names the user just entered. Replacing the video restores the file's metadata. Saving writes the current global clip-duration overrides into the file, and loading a file that specifies them replaces that global store. A file that omits the key leaves the store alone.
- Telestration::Session holds the open video's drawings in normalized picture coordinates. The match session file is what saves them. They are still omitted from the Sportscode XML export.
- EventCodeMap builds the canonical-name ↔ XML-code hashes from EventCatalog main events. Lookup trims and is case-insensitive.
- PresentationQueue manages a sorted vector of selected clips synced bidirectionally with a TagSession, preserving current index across rebuilds, enforcing min durations and video bounds, and emitting Qt signals for UI updates.
- TagSession manages a mutable list of timed GameTags for event marking in game video, maintains derived counts per main/follow-up event, automatically derives quarter/period state from special anchor tags, and supports import with clamping, defaults, and Qt signals for UI reactivity. Core design centers on manual cache maintenance for counts and multi-path state reconstruction for game timing.

## Export

- ClipExporter handles FFmpeg-driven video clipping with QPainter-generated overlays (text, scoreboards, branding), video probing for dimensions/rotation, scaled layout computation, and complex filter_complex graphs ensuring YouTube-safe positioning before concatenation. Dimension, duration, and sidecar probes run off the UI thread. Clip video is h264_videotoolbox (`-hwaccel videotoolbox`, `-q:v 65`) when `ffmpeg -encoders` lists that encoder. The listing is probed once per ffmpeg binary in a child process, cached, and never waited on the UI thread. Otherwise the clip uses libx264 `-preset fast -crf 23`. A VideoToolbox encode that exits non-zero is retried with libx264, and later clips in that export stay on libx264. Both paths write yuv420p H.264 in the same MP4 container with the same audio mapping.
- ClipTrimBar is a QWidget that renders an interactive timeline for clip trimming, with draggable start/end handles, playhead, event marker, range highlight and time labels. Core design relies on bidirectional ms<->pixel conversion functions, mouse-driven clamping to enforce min duration, and direct paintEvent drawing without layout delegates.
- ConcatFileOrderDialog lets a coach join source videos into one continuous video. VideoClipSequence parses filenames, keeps the only copy of the order, and sorts it chronologically; the dialog shows that order as a vertical timeline with drag-and-drop plus up/down controls.
- ExportClipBuilder supplies utilities for sanitized filename generation (for reports and compilations), clip sorting by team/time, and construction of ClipSegment objects that embed overlay text plus dynamically computed timed scoreboard phases from goal tags. The compilation filename and the overlay label use EventLabelResolver. The sidecar `code` stays the XML short code, or the canonical English name when the session has no abbreviation. The filename for Special stays "special" unless that event has a label override, because the catalog star is not a file name.
- ExportJobManager tracks and drives asynchronous ClipExporter jobs (MP4 video and/or XML reports), enforces output-path exclusivity, maintains job state/lifecycle, and publishes snapshots for UI consumption.
- ExportJobsBar is a QWidget that dynamically builds and updates rows of job status UI (name, status text, progress bar, optional cancel/dismiss buttons) by clearing and reconstructing its layout in response to ExportJobManager::jobsChanged signals. The design relies on Qt parent-child ownership for all widgets/layouts and direct lambda slots for per-job actions.
- ExportSettingsDialog implements a Qt QDialog for configuring export of clips or XML tag reports, with dynamic UI (format-dependent controls, auto path suggestions, checkboxes for overlays/notes/audio) driven by TagSession and queued clips. Key design centers on format switching logic, path validation, and result struct population before accept().
- GameMetadataSuggester coordinates two asynchronous LLM queries to xAI's chat API (structured JSON schema outputs) to infer game names/date from filenames and jersey colors from an ffmpeg-extracted video thumbnail. Key design uses generation counters, state flags (namesDone_/thumbnailDone_), and explicit abort paths to manage concurrent ffmpeg QProcess and QNetworkReply lifecycles.
- PlaybackVideoPreparer transcodes MKV/WebM files to a standardized MP4 (using libx264/aac) via an external FFmpeg QProcess for playback compatibility. Key design centers on async process management, cancel flags, a window-modal progress dialog that closes from finished/errorOccurred, and basic error forwarding from stderr. The UI thread does not wait on the process.
- VideoConcatenator orchestrates FFmpeg-based video concatenation via a generated concat_list.txt and QProcess with copy codec +faststart flags. Key design centers on async process management, a window-modal QProgressDialog, runFinished carrying a result snapshot, cancellation guards, and a drag/drop reordering dialog. The UI thread does not wait on the process.
- XaiConfig implements a namespace that retrieves an API key preferring XAI_API_KEY (or legacy AVA_XAI_API_KEY) environment variables over JSON files in Qt standard config locations, with bootstrap() to persist the env key to primary config.
- XmlExporter converts TagSession game tags into a specific XML schema for video analysis tools (LongoMatch/Olympia), synthesizing extra Goal instances when a follow-up has scoresGoal, emitting dual +/− team codes with running scores, and producing an ordered palette in <ROWS>. The match score counts the scoring-goal main event. Shoot-out attempts use isShootout and do not change that score. Label overrides are not written: `<code>` stays the short code (`UC SHOT+`) or the canonical English name, and the document has no event display-name field. A renamed session therefore exports the same XML bytes as the unrenamed session. carpeta.cl and a later import match that code back to the catalog id. The visible name goes to the .clips.json overlay label and to compilation filenames instead.
- XmlImporter parses a specific XML format for event instances (with start/end times, codes, and QUARTOS labels) using QXmlStreamReader driven by a manual state machine of boolean flags; it validates data, sorts by time+ID, and supplies an anchor-instance lookup with fallback logic.

## i18n

- AppLocale implements bilingual (EN/ES) localization. UI chrome stays in one `{english, spanish}` table. Stored tags take their labels from catalog ids through EventLabelResolver. A session label override replaces that text in both languages and is not translated again. Residual token translation still covers home/away, retired follow-up words, and fixture strings that are not in the catalog. Language state is persisted via QSettings.
- LocaleNotifier implements a Qt QObject-based singleton for broadcasting language change notifications via signals. Uses static local variable for lazy-initialized instance and a simple notify method to emit the signal.

## Style

- theme.cpp applies a light theme to the Qt application by switching to the Fusion style, configuring a platform-aware font (Inter with Apple fallback), and loading a QSS stylesheet from embedded resources via a small helper.
- WorkDataView.h configures the shared list chrome (role `workList`, row metrics, selection, alternating rows) used by the tagging event log, the analysis stats tree, and the presentation clip list. Colors and padding stay in `theme_light.qss`.
